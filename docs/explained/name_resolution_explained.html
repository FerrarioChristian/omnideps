Deep Dive: Il Motore di Name Resolution

Documentazione tecnica esaustiva dell'architettura a Query Engine implementata in src/resolver/ (builder.rs, executor.rs), con spiegazione passo-passo della separazione tra costruzione (substitution) ed esecuzione (navigation).

1. Panoramica e Obiettivo

La Name Resolution è la Fase 2 della pipeline di analisi. Questo motore prende l'IR astratto (contenente riferimenti Unresolved) e li trasforma in query algebriche, che vengono successivamente navigate globalmente per risolvere i riferimenti a componenti.

Stato TypeRefSignificatoEsempio
ResolutionQuery(Query) Riferimento matematico sostituito localmente dal Symbol Stack Extract(Find("T"), "f")
Resolved(path) Nome trovato globalmente navigando l'IR — percorso assoluto ["root", "core", "Veicolo"]
External(path) Nome riconosciuto tramite import ma non presente internamente ["external", "db", "Database"]
Failed(path) Tutti i tentativi di risoluzione sono falliti — il nome rimane irrisolto ["UnknownType"]
Primitive(type) Tipo primitivo (Int, Float, Bool, String, Void) — decodificato data-driven Primitive(String)

La pipeline completa in analyzer.rs è:

1. Estrazione CST→IR → 2. Query Building → 3. Query Execution → 4. Dependency Graph

2. Architettura: Costruzione ed Esecuzione

2.1 Separazione delle Responsabilità

A seguito di iterazioni architetturali profonde, l'infrastruttura è stata separata matematicamente in due fasi rigorose. Le variabili locali (es. i) non sono componenti architetturali veri e propri, bensì astrazioni passeggere. Di conseguenza, la logica di valutazione in tempo reale è stata spaccata in due passaggi asincroni:

Phase 1: Query Building (Substitution)

Un ambiente effimero (il Symbol Stack) viene istanziato all'entrata di una funzione. Non effettua risoluzioni, ma applica pura sostituzione sintattica sulle variabili oscurate. Quando la funzione termina, il Symbol Stack si autodistrugge. Lascia indietro unicamente costrutti ResolutionQuery privi di contesto locale.

Phase 2: Query Execution (Navigation)

Avendo purificato l'IR da variabili fittizie, un navigatore globale (l'Executor) riceve in carico i nodi Query e li valuta salendo e scendendo per l'albero di tutti i componenti del progetto ormai letti e conosciuti.

3. L'Algebra delle Query

Ogni espressione è formata dalla combinazione di sole tre primitive matematiche definite nell'enum Query (in model/queries.rs):

pub enum Query {
    Find(String),
    Extract(Box<Query>, String),
    Call(Box<Query>),
}
  • Find("a"): Cerca a salendo (find-going-up) lungo gli scope genitori.
  • Extract(Q, "b"): Valuta Q, poi scende (find-going-down) al suo interno cercando b.
  • Call(Q): Valuta Q invocandolo come funzione, estraendone il tipo di ritorno.

Vantaggi dell'Astrazione: Grazie a questa netta divisione in due step, l'Analizzatore ottiene una vera semantica lessicale, diventando infinitamente più resiliente all'ordine di dichiarazione (risolve nativamente i forward-references) e scartando completamente l'onere di mantenere in memoria tabelle di scope annidati durante la fase di risoluzione effettiva.
