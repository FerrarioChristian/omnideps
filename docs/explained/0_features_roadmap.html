Language-Agnostic Analyzer: Features & Roadmap

1. Dipendenze di tipo (Type-Level)

Feature Stato Esempi & Differenze Linguistiche Modellazione (IR & Grafo) Implementazione (Heuristics)
Class / Struct / Interface / Trait Sì 
class User { } // Java, C++, Py
struct Data { } // C, Rust
trait Walk { } // Rust
interface Fly { } // Java
Riconoscimento unificato. Estrazione perfetta in Rust. In C++ estrae le classi. In Java estrae Classi e Interfacce. In Python le dichiarazioni non hanno keyword rigide come struct, ma `class` viene estratto. In C le struct vengono riconosciute correttamente includendo il parsing ricorsivo. Tipi locali (all'interno dei body delle funzioni) vengono annidati correttamente. Ricerca raffinata per evitare falsi positivi (es. esclusi i costruttori `constructor_declaration` in Java/C++ che contengono la stringa 'struct').
 Nodo: StructuredType
Grafico: Vertice primario		 try_parse_structured_type
Riconosce i nodi CST (class_declaration, struct_specifier, ecc.).
Variabili Tipate (Fields) Sì 
private String name; // Java
            pub age: u8, // Rust
            char *id; // C
Supportato per tutti i linguaggi. L'estrattore strutturale naviga la gerarchia della classe bloccandosi intenzionalmente all'ingresso dei metodi (!is_function(child)), garantendo che le variabili locali dichiarate all'interno delle funzioni non vengano erroneamente promosse a campi della classe.
 Campo: Field dentro StructuredType
Arco: UsesFieldType		 extract_fields
Firme di Funzioni (Parametri & Ritorno) Sì 
int sum(int a, float b) // C++
fn run(user: User) -> bool // Rust
Funziona in Rust, Java, e Python. Python non forza type hints; se mancano o se il ritorno non è specificato, fallisce elegantemente a Void o Failed. In C++ i metodi vengono estratti correttamente navigando il nodo function_declarator. In C le funzioni all'interno delle struct tramite puntatore sono correttamente categorizzate come campi.
 Entità: Function con Signature
Archi: UsesParamType, UsesReturnType		 extract_parameters, extract_return_type
Generics / Template No 
Map<K, V> map; // Java
vector<int> vec; // C++
 Attualmente estratti come tipo base grezzo (Map o vector).
Idea di implementazione: Aggiungere pub type_arguments: Vec<TypeRef> al TypeRef nell'IR. In `extract_type_ref`, intercettare nodi come `type_arguments` o `template_argument_list`, estrarne i figli e generare archi UsesGenericType verso `K` e `V`.
 -
Type Alias Sì 
type UserId = string; // TS
typedef int length_t; // C
 Gli alias vengono parsati in Component::TypeAlias, registrati nel ScopeTree e risolti trasparentemente dal Executor generando nodi e archi grafici dedicati. Nodo: TypeAlias
Arco: Aliases
Type Casts Sì 
let a = x as i32;
int b = (int) c;
 Parsati durante l'ispezione dei blocchi e salvati nel Block come referenze di tipo castate. Arco: CastsTo
Union Types Sì 
User | Admin // TS
Union[str, int] // Python
 L'implementazione estrae tutti i termini dell'unione in un costrutto TypeRef::Union(Vec<TypeRef>). Il grafo genera automaticamente un arco UsesType / UsesReturnType per ciascun tipo che fa parte dell'unione. try_parse_structured_type, type_ref_targets
Type Constraints No 
<T extends Serializable>
Idea di implementazione: Molto complesso in un'architettura agnostica. Si potrebbe modellare introducendo un "nodo fantasma" nel modulo per rappresentare T, per poi fargli ereditare (`IsA`) da Serializable. I parametri generici punterebbero quindi a questo nodo fittizio.
 -
Inferenza Tipi Locali (auto/let) Sì 
let db = Database::new(); // Rust
auto repo = new Repository(); // C++
L'analizzatore supporta un'inferenza "best-effort": se la dichiarazione non esplicita il tipo (es. let x = ...), il sistema scruta l'inizializzatore. Se è un'istanziazione esplicita, il tipo viene dedotto e salvato correttamente nel SymbolStack.
 Costrutto Field nel Block infer_variable_type
Return Type Impliciti / Inferenziali N/A 
func f() { return User{} }
Perché Non Sì: L'inferenza locale richiede di tracciare l'albero delle espressioni fino ai nodi foglia, simulando l'esecuzione statica. Questo distrugge l'astrazione agnostica e va lasciato ai compiler veri e propri. L'approccio corretto è segnarlo come Failed o Void e ignorarlo a livello architetturale.
 -

2. Dipendenze da Chiamata (Call Graph)

Feature Stato Esempi & Differenze Linguistiche Modellazione (IR & Grafo) Implementazione (Heuristics)
Function / Method Calls Sì 
foo(); // OK
User.create(); // OK
myVar.run(); // OK
self.get_id(); // OK
Supporto completo grazie al Lexical Scoping Comportamentale. Le variabili locali (incluse le elisioni inferite tramite infer_variable_type) vengono estratte in un albero di blocchi e registrate nel SymbolStack per risolvere l'oggetto chiamante. Inclusa l'auto-registrazione in scope per self e this.
 Gerarchia di Block dentro Function
Archi: Calls, UsesLocalType		 extract_block, resolve_block
Factory / Static Methods Sì 
User::create(); // C++, Rust
DatabaseFactory.build(); // Java
 Vettore: calls in Function
Arco: Calls (risolto nel Global Scope o come External Import).		 traverse_for_body_deps
Constructor Calls Sì 
new User(); // Java, C++
User {} // Rust
User() // Python
 Vettore: instantiates nel Block di una Function
Arco: Instantiates		 extract_block
Ricerca di object_creation_expression o struct_expression.
Operator Overloading No 
a + b // C++
Idea di implementazione: Pre-processing durante l'estrazione. Marcare un metodo come "operatore" se il suo nome inizia per operator. Nel parser dei body, i nodi binary_expression (es. `+`) verrebbero estratti non come keyword, ma tradotti in ipotetiche dipendenze di tipo CallsOperator. Trattandosi di tipizzazione dinamica delle variabili, il rischio di Failed è altissimo.
 -

3. Dipendenze da Accesso (Usage-Level)

Feature Stato Esempi & Differenze Linguistiche Modellazione (IR & Grafo) Implementazione (Heuristics)
Accesso a Proprietà/Campi d'Istanza Sì 
user.name = "Mario";
 Il costrutto V3 risolve perfettamente questo caso tramite la sostituzione lessicale: user.name diventa Extract(Find("user"), "name"). Il Resolver trova la variabile locale user, ne estrae il tipo, cerca lo Scope della classe e valida l'esistenza del campo name. Viene generato un arco AccessesField con destinazione precisa. evaluate_query_extract
Accesso Statico / Variabili Globali Sì 
Math.PI;
 Il Query Engine bifase divide `Math.PI` in Extract(Find("Math"), "PI"), validando prima l'esistenza di `Math` (nel file o tramite import) e poi verificando che possieda un membro statico `PI`. Emette un arco AccessesField. evaluate_query_extract
Enum Usage Sì 
Status.ACTIVE
 Stessa identica logica dell'Accesso Statico. L'albero degli scope naviga Extract(Find("Status"), "ACTIVE"), restituendo il percorso assoluto alla variante dell'enum. L'arco emesso è AccessesField. evaluate_query_extract

4. Dependency Injection e Wiring

Feature Stato Esempi & Differenze Linguistiche Modellazione (IR & Grafo) Implementazione (Heuristics)
Annotazioni e Decorator Sì 
@Autowired
@Inject
#[derive(Debug)]
 I meta-dati vengono estratti e aggiunti come annotations: Vec<TypeRef> in StructuredType, Function e Field. Il generatore di grafo esporta queste relazioni usando archi di tipo AnnotatedWith. Funziona agnosticamente anche con gli attributi Rust e le direttive C++. extract_annotations
Constructor Injection Parz 
new Service(repo);
 Il tipo del parametro è riconosciuto strutturalmente (UsesParamType). Il "wiring" dinamico di framework è ignorato in quanto non riconoscibile staticamente -
Reflection / Dynamic Lookup N/A 
Class.forName("User")
Perché Non Sì: La valutazione di stringhe a runtime rende invisibili le dipendenze al parser statico. È un limite teorico dell'analisi statica pura.
 -

5. Dipendenze Ereditarietà

Feature Stato Esempi & Differenze Linguistiche Modellazione (IR & Grafo) Implementazione (Heuristics)
Inheritance Sì 
class A extends B // Java
class A : public B // C++
 Vettore: super_types
Arco: IsA		 extract_super_types
Implementation Sì 
class C implements D // Java
 Unificato nel vettore: super_types
Arco: IsA (unificato in modo agnostico per semplicità)		 extract_super_types
Trait / Impl Blocks Sì 
impl Trait for Struct // Rust
 Modulo IR temporaneo: ImplBlock (appiattito dal Risolutore).
Arco: Implements		 try_parse_impl_block, resolve_impl_block
Mixins No 
class A with B
Idea di implementazione: Aggiungere i nodi sintattici tipici dei mixin (es. `with_clause`) a `extract_super_types`. Una volta estratti in `super_types`, l'analizzatore creerà naturalmente l'arco IsA.
 -
Method Override Parz 
@Override void do()
Idea di implementazione: Per tracciare esplicitamente un arco Overrides, il risolutore finale dovrebbe navigare l'arco IsA della classe corrente, ispezionare la classe padre in Σ, verificare se esiste una funzione con la stessa firma σ, e in caso affermativo generare l'arco aggiuntivo.
 -
Protezione Ereditarietà Ciclica (MRO) Sì 
class A(B) ... class B(A)
 Tracciamento dei nodi visitati in un HashSet per prevenire cicli infiniti nella ricerca dei metodi. find_member

6. Dipendenze da Controllo di Flusso

Feature Stato Esempi & Differenze Linguistiche Modellazione (IR & Grafo) Implementazione (Heuristics)
Exception Handling No 
catch (IOException e)
Idea di implementazione: Aggiungere `catches: Vec<TypeRef>` in `Block`. In `extract_block`, intercettare i nodi `catch_clause`, estrarne il tipo dell'eccezione, e poi generare un arco CatchesException nel grafo.
 -
Throw Parz 
throw new MyException()
Idea di implementazione: Attualmente l'istanza interna new viene catturata in `instantiates` da `find_behavioral_deps`. Per differenziarla, `find_behavioral_deps` dovrebbe controllare se il genitore dell'espressione è un nodo `throw_statement`. Se sì, aggiungere il tipo in un vettore dedicato `throws` in `Block` piuttosto che `instantiates`.
 find_behavioral_deps

7. Dipendenze da Macro / Metaprogrammazione

Feature Stato Esempi & Differenze Linguistiche Modellazione (IR & Grafo) Implementazione (Heuristics)
Macro No 
println!("Hello") // Rust
#define MAX 10 // C
Idea di implementazione: Molto critico per Rust e C++. L'approccio più ortodosso sarebbe eseguire un comando di pre-processing nativo (es. `cargo expand` o `gcc -E`) prima di passare il codice all'analizzatore Tree-sitter. In alternativa, si tracciano ciecamente i nodi `macro_invocation` come fossero `Calls`.
 -
Code Generation (es. Lombok) N/A 
@Data class User {}
 L'analizzatore guarda il sorgente grezzo prima della compilazione. Se getter/setter non ci sono non verranno visti. -

8. Moduli e Linking

Feature Stato Esempi & Differenze Linguistiche Modellazione (IR & Grafo) Implementazione (Heuristics)
Imports / Include Sì 
use std::vec::Vec; // Rust
#include <iostream> // C++
 Vettore imports in Module (i "Jump Points"). Il TypeRef assume stato External se non corrisponde a nodi in memoria locale. try_parse_import, resolve_name_in_context
NameSpaces / Modules Usage Sì 
mod core { } // Rust
        namespace math { } // C++
        package com.api; // Java
Annidamento ricorsivo e diversificazione strategica supportata tramite `ModuleStrategy`. Funziona in Rust (`mod` e file-based), C++ (`namespace`), Java (`package_declaration`) e Python (dove i file e le directory `__init__.py` vengono automaticamente mappati in gerarchie di moduli senza appiattimenti nel root).
 Annidamento ricorsivo di Module.
Arco: Mappato come gerarchia parent in Cytoscape.		 try_parse_module_node, try_parse_package_declaration, Logica in analyzer.rs
Dynamic Imports N/A 
import('./module') // JS
 Richiede esecuzione comportamentale a runtime, incompatibile con la lettura AST statica. -
Re-Export No 
pub use crate::other::Type;
Idea di implementazione: L'analizzatore dovrebbe riconoscere il modifier `pub` di un import. Il Risolutore inserirebbe l'Alias dell'import direttamente nella `Symbol Table` (Σ) associandolo al `ResolvedName` originale, permettendo ai file dipendenti di vederlo come se fosse dichiarato localmente.
 -
Transitive Imports (es. Python) Sì 
import A
Dove A importa B, permettendo l'uso di A.B.Component
 Supportato tramite la configurazione linguistica transitive_imports che permette all'ExecutorContext di ri-esportare la visibilità degli import nei moduli dipendenti. get_all_module_imports
Forward Declarations Sì 
class Car; // C++
void run();
Permette la dichiarazione disaccoppiata dall'implementazione (header/source) tipica di C/C++.
 Supportato tramite un passo di pre-processing (link_out_of_line_methods) governato dal flag forward_declarations, che fonde i corpi delle funzioni fuori-linea nelle dichiarazioni originali all'interno delle classi o interfacce. link_out_of_line_methods
